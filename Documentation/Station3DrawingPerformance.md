# 第三台画图工位性能复测

第三台的 CAD 配置含 123 个运动零件和 1,679 个静态零件。原绘图防穿模逻辑逐帧重算固定零件的包围盒，每个扫掠姿态还要对所有运动零件逐一遍历候选障碍。笔尖离纸越近，连续运动验证需要的采样就越密。

修改后，固定零件由空间树索引。一次世界包围盒查询即可排除整组远处零件，靠近机械臂、夹具和笔尖的零件仍走原有精确包围盒及连续关节扫掠。静态零件被移动、隐藏或重新启用时，索引随之更新。

## 原场景同轨迹对照

基线取自 Git 版本 2d5ea12，在同一台机器、同一 Unity 2022.3.61f1c1 Editor、同一场景中输入 390 次固定 1/30 秒的步进。用同一计时方法测机械臂运动更新和落笔记录。单位为每次更新的毫秒数，整帧还包含渲染和 UI。

| 阶段 | 次数 | 原版中位 | 新版中位 | 原版 P95 | 新版 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 持笔悬停 | 60 | 7.74 | 1.14 | 8.10 | 1.49 |
| 从上方降到纸面 | 30 | 57.46 | 5.13 | 72.54 | 6.33 |
| 纸面停笔 | 60 | 7.71 | 1.14 | 7.99 | 1.52 |
| 纸面直线来回 | 120 | 24.76 | 2.64 | 31.36 | 3.12 |
| 纸面圆弧 | 120 | 50.96 | 4.75 | 62.63 | 5.83 |

两次运行产生同样的一笔，共 121 个顶点，总长 0.296 米。直线和圆弧的平均扫掠区间数分别保持为 2.925 和 7.083，两组的安全轨迹拦截次数均为 0。独立构造的薄障碍检查 9/9 通过，覆盖两个安全端点之间发生碰撞、拒绝后关节恢复，以及移动和显隐障碍后仍能正确拦截。

实际示教器另外暴露出高帧率运行会停住的两个原因。一次实测帧间隔为 1.69 ms，每步只能前移约 0.15 mm，比原 IK 的 0.4 mm 到位容差还小，导致真实笔尖留在原地。现在每个空间步的 IK 容差取原容差和本步半程的较小值。第二处发生在抬笔接近纸面时，示教器须等真实机械臂到达当前子步的目标高度，不能将纸面上方的合法子步提前算成纸面高度。落笔、工作空间和关节角速度的约束保持生效。

高帧率诊断以 1/600 秒步长通过正常的运动控制和碰撞检测，旧版实际笔尖行进 0.000 mm，新版行进 11.999 mm 到达 12 mm 目标。基准 JSON 的 fastFrameTravelMm 和 fastFrameEndErrorMm 记录此项。用旧代码重跑时，该项会在写出基准数据后报错。

最终普通 Windows 版构建 0 错误、0 警告。通过实际示教器按钮和原场景运行，程序执行验收 194/194、录点验收 146/146。执行验收记录真实工具位置，覆盖单步、暂停和恢复、急停、直线、三点圆弧、落笔和无痕回程、存取程序以及第二台套圈。两处示教器画面截图均通过非黑帧检查。

## 在组员电脑复测

结束当前打开该工程的 Unity，在 PowerShell 中把编辑器路径改成本机的 Unity 2022 安装路径。以下命令会运行上述 390 帧对照轨迹和 9 项防穿模检查，写出每项的中位、P95、扫掠区间、末端位置和笔迹统计。

~~~powershell
$editor = 'C:/Program Files/Unity/Hub/Editor/2022.3.61f1c1/Editor/Unity.exe'
$project = 'D:/dachuang-unity'
Start-Process $editor -Wait -ArgumentList @('-batchmode','-nographics','-quit','-projectPath',$project,'-executeMethod','RoboticsLab.Editor.LabDrawingPerformanceValidation.Run','-logFile',"$project/Logs/DrawingBenchmark.log")
Get-Content "$project/Logs/DrawingBenchmark.json"
~~~

组内若要在旧版重复基线，在独立副本中使用 2d5ea12，将新版的 Assets/RoboticsLab/Editor/LabDrawingPerformanceValidation.cs 及其 .meta 同样复制过去，再运行上述命令。编辑器菜单 Robot Lab → Diagnostics → Validate Drawing Obstacle Sweep 可以单独验证障碍物检测。
