# 控制器 L / C 示教、运行和程序文件

使用 Unity 2022.3.61f1c1 打开主工程，场景为 `Assets/RoboticsLab/Scenes/RoboticsTrainingRoom.unity`。完成安全帽、墙面教学与问答后，进入 02 套圈或 03 画图工位，点击“示教器 / L・C 编程”。01 工位继续使用专用循迹流程。

控制器沿用组员 `kongzhiqi` 工程的外观和按键布局。点位录入、程序列表、当前执行行和文件菜单都显示在控制器 LCD 内。完整运行信息和阻挡原因也会显示在场景中间底部的信息条。

## 按键操作

| 按键 | 功能 |
|---|---|
| F1 | 记录真实工具当前位置，新增一条 `L P[n]` 直线指令。可鼠标点击，也可按键盘 F1。 |
| F2 | 第一次记录 C 的中间点，移动工具后再按一次记录终点，补全同一条 C 指令。 |
| ENTER | 继续按当前 L / C 模式记录；已有未完成 C 时补录它的终点。 |
| F3 / Backspace | 撤销最后一条指令；不更改此前点号。仍被其他指令引用的点会保留。 |
| F4 | 切换后续新指令速度：100 → 50 → 150 → 100 mm/sec。 |
| F5 | 清空当前工位的程序和点位，下一点重新为 P[1]。 |
| FWD | 从头运行；已 HOLD 暂停时，从暂停位置继续。完成或故障后再次按下，会重新从头预检并运行。 |
| HOLD | 暂停当前轨迹并停止落笔，保留当前行和轨迹进度。按 FWD 明确继续。 |
| STEP | 执行一整条 L 或 C 指令，并在真实工具 FINE 到位后暂停；再次按下执行下一条。不是只走一小步。 |
| RESET | 停止 L/C 程序并释放手动控制，保留全部示教点和程序行。它不等于“工位复位”。 |
| DATA | 在 LCD 内打开或关闭程序文件菜单：保存、加载、回 P[1]。 |
| 控制器急停按钮 | 触发或解除训练急停。解除后不会自动恢复轨迹，仍需按 FWD。 |
| J1± / J2± / J3± | 按住点动：台面左右、台面前后、工具升降。松开停止。 |

场景原有点动按钮及 WASD、Q/E 也可用于示教。程序运行或 HOLD 暂停期间，手动点动、示教录点、撤销、清空和加载都会锁定；先按 RESET，再修改程序或移动工具。输入文件名时，键盘不会同时触发点动或示教快捷键。滚轮可查看较长的 LCD 程序列表。

## 先示教，再运行

推荐先记录一条抬笔 L，用于回到本次图形的起点。随后设置合适的画笔状态，移动到每个终点并记录后续 L；圆弧依次记录中间点和终点。需要闭合图形时，可使用 DATA 的“回 P[1]”。最后按 FWD，从第一行开始执行。

例如：

```text
1:L P[1] 100mm/sec FINE
2:L P[2] 100mm/sec FINE
3:C P[3] P[4] 100mm/sec FINE
4:L P[1] 100mm/sec FINE
[End]
```

这里第四行复用已有 P[1]，不会创建一个相同坐标的新点。第二行结束的 P[2] 是第三行圆弧的起点，P[3] 是圆弧必须经过的中间点，P[4] 是终点。首行的运动起点则取按下 FWD 时真实工具的位置。因此，示教点位和指令行号分别计数，C 占一行、引用两个点。

只录了中间点时，C 行显示 `P[?]`。这种草稿可以保存、加载、继续补录，但不能运行。应先补录终点，或撤销该 C 行。三个点重合、三点共线或接近共线的圆弧会在运行前明确拒绝；需要整圆时，示教两段圆弧。C 使用真实三点圆弧插补，按经过中间点的方向运行，支持大于半圆的弧段。

STEP 到最后一行会正常完成程序；运行结束、RESET 停止或出现故障都会停止落笔。HOLD 会暂时停止落笔，恢复时按当前行记录的状态继续。关闭示教器、离开工位、切换模式或工位复位会停止程序，之后必须明确重新运行；窗口失去焦点时会 HOLD 暂停。

## 画笔和轨迹约束

每行同时记录当时的落笔/抬笔状态。03 工位先在场景操作区设置画笔状态，再按 F1/F2 录点。一个 C 段以第一次记录中间点时的画笔状态和速度为准，录入它的两个点期间应保持一致。

目前“抬笔”指 `PenDown=false`，控制是否生成笔迹，不会自动增加竖直抬高动作。返回首点前先按 P 切到抬笔，再追加 `L P[1]`，回程就不会留下连接线。如需实际升高笔尖，应在抬笔后用升降点动或另行示教空间接近/离开点。

落笔轨迹的起点、中间点和终点必须都在纸面。需要从上方接近纸面时，先用一条抬笔 L 到纸面起点，再示教落笔 L/C；程序不会把空间圆弧强行压成平面。纸面接触只允许很小的 IK 高度误差。示教时若已留下笔迹，可以使用场景“重置 [R]”清除笔迹并复位工具，程序行仍保留；然后由第一条抬笔 L 重新接近纸面。

02 工位使用实际圆环中心作为示教工具位置，不能落笔。套圈和画图都继续经过原来的 `LabRobotStation.MoveTool`、Group0927 IK 和碰撞检查。执行器不会直接修改关节、末端或目标 Transform，不会为了到达点位绕过钢丝边界、端点或机械臂碰撞约束。

启动前会预检完整程序，包括点位引用、C 是否完整、圆弧退化、速度、整段工作区边界和落笔平面。圆弧边界使用解析坐标极值检查，不能靠裁剪轨迹来通过。运行时按弧长推进并等待实际 TCP 跟上；C 的中间点和每条指令的终点都会等待真实工具 FINE 到位。绘图终点公差为 1 mm，套圈为 0.35 mm。碰撞持续阻挡、无进展、轨迹偏差或超时会停止并显示故障，不能跳过问题行假装完成。

## 速度和进给限速

LCD 行中的 `100mm/sec` 是该条指令的标称速度。参数范围为 1–1000 mm/sec，实际进给同时受当前工位的 `moveSpeed` 限制。例如当前工位上限为 88 mm/s，100 或 150 的指令会按最多 88 mm/s 进给，状态信息显示“指令 100 / 限速 88 mm/s”。50 的指令按最多 50 mm/s 运行。

IK 跟随、FINE 到位和低帧率下的圆弧空间细分还可能降低实际速度。不会为了达到标称速度提高工位配置或跳过碰撞检查。F4 只影响后续新录入的行，已经示教的行保持原速度；C 的两个点共用同一行的速度。

## DATA：保存、加载和回到首点

点击 DATA 后，在 LCD 的文件菜单输入程序名并按“保存”；也可以从列表选择已有程序后按“加载”。文件保存点号、坐标、L/C 类型、中间点引用、速度和画笔状态。02、03 工位的文件分别管理。关闭并重新启动应用后，可再次从 DATA 加载，随后在当前工位预检并运行。

“回 P[1]”是在当前程序末尾追加一条引用首个已示教点的 L 指令，通常为 `L P[1]`，它不会立即移动机械臂。追加行采用当前速度和画笔状态；关闭 DATA 后按 FWD 才执行。撤销后继续示教时点号可能不再从 1 开始，此功能仍引用当前程序保留的第一个点。程序有未完成 C 时，先补齐或撤销后再追加返回行。

文件加载会检查点号唯一性、所有引用、速度和坐标有效性；损坏的数据不会替换当前程序。运行或暂停时禁止加载和编辑。原“高级轨迹编辑”与示教器是各自独立的程序数据，二者运行与暂停互斥；停止当前程序后才能切换执行另一种程序。

## 模块职责

- `LabPendantProgramModel`：稳定点号、L/C 指令、两阶段圆弧录入、画笔状态、JSON 数据校验和数据版本号。
- `LabPendantMotionPath`：独立的直线/三点圆弧几何、弧长采样和解析边界。
- `LabPendantExecutor`：运行、单步、暂停和恢复，程序快照、进给限速、FINE 到位与故障处理。
- `LabPendantController`：实体图片按钮接线、当前工位和文档绑定、真实 TCP 录入、画笔状态与文件入口。
- `LabPendantScreenView` / `LabPendantFilePanel`：LCD 程序列表、当前行高亮、状态与文件菜单。
- `LabPendantProgramStorage`：各工位程序文件的本地保存和加载。
- `LabPendantJogButton`：按住/释放点动事件，运动继续交给工位适配器。

控制器依赖位于 `Assets/ControllerUI`，保留组员原资源 GUID。不要把整个嵌套 Unity 工程再次复制进主工程 Assets，以免重复导入标准 TMP 资源。

本项目是虚拟机器人训练。控制器的急停、HOLD、RESET 和进给速度用于本仿真场景，不与实体机器人控制柜或硬件安全回路联控。

## 只展示 L/C 的慢速录制流程

根目录 `Play L-C Recording.cmd` 可启动约 3 分 40 秒的连续演示：真实 TCP 录点、L 直线、C 中间点与终点、回 P[1]、运行/暂停、完整指令单步、保存/清空/加载、重新执行及急停恢复。字幕说明当前步骤，黄色框标出控制器按钮；演示完成后保留程序和画作。

该入口专为只录制 L/C 功能而设，会直接初始化已解锁的 03 工位。普通启动保留安全帽、墙屏学习和问答要求。源码中的演示模块位于 `Scripts/Demo`；普通 Windows 构建加 `--recording-showcase` 参数即可启用，也可通过 `Robot Lab > Build L-C Recording Demo` 单独构建到 `Builds/Recording`。
