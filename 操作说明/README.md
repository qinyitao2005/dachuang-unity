## 后面怎么交

1. 改完功能后，在这里新建或更新对应功能的使用说明，文件名写清工位和功能。
2. 至少写清楚：改了什么、从哪里打开、按什么顺序操作、怎么看结果、哪些还没做或没测。
3. 用了 AI，就补上它主要帮忙做了什么，以及实际检查到哪一步。AI 说“完成”不等于已经在 Unity 跑通。
4. 本地测试过再写“已测试”。只编译过、只看过代码，或者要交给别人验收，也直接说明。
5. 把说明和功能代码一起提交，并更新上面的目录。同一份操作步骤保留一个正式版本，其他位置放链接即可。

可以把[说明模板](说明模板.md)直接交给 AI，并附上这句话：

> 功能写完后，请在仓库根目录的“操作说明”文件夹生成或更新使用说明，按现有模板写清入口、操作步骤、修改内容、AI 参与范围、验证结果和未完成项，并更新目录。不要把没运行过的功能写成已验收。

实验室不允许改速度。三台新示教器指令均维持 20 mm/sec，没有调速入口；后续涉及速度的修改先找本次提交者确认。

有不清楚、运行不起来或者做不下去的地方，直接联系我（本次提交者）。涉及其他人的工位，也先和对应负责人沟通。

这个文件夹和里面的说明会随 Git 一起同步。之前没有出现在 Git 改动里，是因为文件夹为空；Git 跟踪文件，不单独跟踪空文件夹。
